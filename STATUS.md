# STATUS — состояние проекта на 2026-10-10 (вечер)

Миссия: `MISSION.md` — первый реальный платёж от клиента в Молдове.
Проект: маркетплейс аренды/продажи жилья в Кишинёве. Telegram-бот + Mini App, бесплатные объявления, платный Boost.

## ❌ НЕ РАБОТАЕТ / НЕ СДЕЛАНО

### Критично для первого платежа

- [ ] **Денег нет.** `REAL_REVENUE = 0` по всем трём рельсам. Карточный рельс упирается не в код, а в два человеческих шага: аккаунт Lemon Squeezy + публичный HTTPS (вебхук физически не может приходить на 127.0.0.1). Stars-рельс упирается в покупателя: без карты, привязанной к Telegram, покупка звёзд отдаёт `PROVIDER_ACCOUNT_INVALID`, а при 0 звёзд Telegram на экране оплаты пишет «метод оплаты невалиден для этого типа товара»; тестовые XTEST-инвойсы прод-боту запрещены (`PAYMENT_PROVIDER_INVALID`).
- [ ] **Нет аккаунта Lemon Squeezy** → `LS_API_KEY/LS_STORE_ID/LS_VARIANT_ID/LS_WEBHOOK_SECRET` пустые, `CARD_ENABLED=False`, кнопки «💳 Картой $5.00» клиент не видит. Молдова поддерживается LS как страна выплат мерчанту — это единственный «как у людей» путь без юрлица.
- [ ] **Нет домена/TLS** → не только Mini App недоступна (кнопка «Открыть приложение» скрыта), но и **карточная касса не может работать**: `GET /v1/orders` не отдаёт `custom_data`, так что атрибуция заказа существует только в вебхуке. nginx + certbot уже стоят, порты открыты — нужна только A-запись.
- [ ] **Возврат/чарджбек не снимает начисленный Boost**: `order_refunded` сохраняется в `card_orders`, но `applied` не откатывается — до первых продаж это ручной шаг админа.
- [ ] **Цены рельсов не сходятся**: 50 Stars ≈ $0.5 против $5.00 картой и 100 MDL — клиент может выбрать самую дешёлую лазейку. Решение (поднять `BOOST_STARS` или выключить рельс) за человеком.
- [ ] **Рельс MDL не заполнен:** `PAY_INFO` пустой — покупатель видит «реквизиты пришлёт модератор». Нужно вписать карту/счёт в `.env`.
- [ ] **Доска пуста**: listings = 1 (ДЕМО-карточка для теста кассы), реальных объявлений **0**, boosts 0, payments 0. Без объектов Boost продавать нечего — это главный блокер, а не код.
- [ ] **Нет источника легальных объявлений** (50–100 объектов). Scraping 999.md запрещён миссией (ToS + чужие фото).
- [ ] **AI не используется** (классификация, нормализация, дедуп, генерация описаний).

### Сервер / безопасность

- [ ] `ufw` теперь пропускает 80/443 (включено намеренно, ради вебхука и Mini App) — когда домен оживёт, снаружи появится публичный HTTP-эндпоинт; единственная защита вебхука — HMAC-подпись, остальной API только читает
- [ ] nginx работает, но **сервер-блок ещё не под домен** и сертификат не выпущен (`apply_https.sh` делает это одной командой)
- [ ] Оба сервиса работают от `root`, нет незаинтересованного пользователя
- [ ] **Нет бэкапов** SQLite-БД
- [ ] Нет rate limit и защиты от спама объявлениями
- [ ] Когда-то висевший `python3 -m http.server` из `/root` — проверить, что убит (риск отдачей `.ssh/`)
- [ ] Токен бота когда-то был вписан в 3 deploy-скрипта; вырезан из кода **и из истории git** до первого пуша. На всякий случай стоит отозвать через @BotFather (`/revoke`) и обновить `.env`

### Функции

- [ ] Нет возврата средств (только `/paysupport`), нет expiry-уведомлений о закончившемся Boost
- [ ] Нет текстового поиска; фильтр по цене/комнатам только в API

## 📌 СЛЕДУЮЩИЕ ШАГИ

Цель — **первый реальный доллар за неделю**. Код кассы готов и проверен; не хватает четырёх
человеческих действий. Порядок = по скорости влияния на деньги.

1. **Человек (5 мин): домен с A-записью на IP VPS** (для `.md`-зоны нужен локальный presence; дешёвый
   вариант — обычная `.xyz`/`.eu.org`/`.online` зона, registrant может быть любой). Без этого шага
   карточная касса и Mini App не работают в принципе: nginx + certbot уже стоят, порты открыты.
   Как только запись проставлена — одна команда (я могу выполнить сам, если дан доступ):
   `bash /tmp/apply_https.sh <домен>` → HTTPS + `WEBAPP_URL` + «401» из вебхука как признак жизни.
2. **Человек (15 мин): аккаунт Lemon Squeezy** → store → один товар «Boost» → прислать мне
   `LS_API_KEY`, `LS_STORE_ID`, `LS_VARIANT_ID`; я вписываю в `.env`, ты регистрируешь вебхук
   `https://<домен>/webhook/lemonsqueezy` (события `order_created, order_processed, order_refunded`)
   с signing secret → `LS_WEBHOOK_SECRET`. После этого у клиента появляется «💳 Картой $5.00».
   Banking (вывод на счёт) — Молдова поддерживается, заполняется в том же дашборде.
3. **Человек (2 мин): `PAY_INFO`** — карта/счёт для перевода MDL в `/opt/imobiliare/bot/.env` +
   `systemctl restart imobiliare` (страховочный рельс, пока LS не пройден). Затем тест без денег:
   ДЕМО-карточка → «💸 Переводом 100 MDL» → «Я перевёл» → заявка админу → «✅ Деньги пришли»
   (Boost активится, `/stats` покажет 100 MDL — тестовые строки после прогона снять, §11 RUNBOOK).
4. **Человек (главное): 3–5 реальных объявлений** — продавать Boost нечего, пока доска пуста.
   Шаблоны и ссылки с `?start=` — в `GROWTH.md`.
5. **Я после шагов 1–2:** прогнать `test_card_rail.py` уже с реальным секретом LS, сделать тестовый
   заказ в LS-mode (`test_mode=1` начислит Boost, но не попадёт в выручку), затем первый настоящий
   платёж на $5 со своей карты и сверить `REAL_REVENUE Картой` + выплату в Banking.
6. Реестр источников трафика → после 5 оплат поднимать цену Boost.
7. Бэкап БД (cron `.backup` + ротация) и отдельный пользователь под сервисы.
8. Локальный эквайринг MDL (maib/bpay/Fastpay) и нормальный учёт — нужен ÎI/SRL; теперь это опция
   развития, а не блокер: LS закрывает «как у людей» уже сегодня.
9. Решение по ценам: 50 Stars ≈ $0.5 — дешевле карточного рельса в 10 раз. Поднять `BOOST_STARS`
   (например до 500) или выключить рельс, пока он не стал дырой.
